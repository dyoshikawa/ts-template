# Project Overview

This repository starts from ts-template: a TanStack Start (React) app styled with Tailwind CSS v4
and deployed to Cloudflare Workers, with passwordless email sign-in, an installable PWA and Web Push
notifications. The UI is written in English.

- Every screen must work on a phone first: 44 px tap targets, 16 px inputs (`src/components/ui.ts`),
  and dark mode through `dark:` variants on every component.
  Never give a form control a text size under 16 px: iOS zooms into it on tap.
- The Content-Security-Policy (`contentSecurityPolicy` in `src/lib/security-headers.ts`) allows
  scripts only with the per-response nonce. Never add `'unsafe-inline'` or `'unsafe-eval'` to
  `script-src`; a new third-party origin (images, frames, fetches) is added to its directive there.
- Server functions must validate input with `zod/mini` and scope every read and write to the
  signed-in user, whose session comes from Better Auth on the server, never from the client
  (`requireUserId` in `src/lib/auth-server.ts`).
- A new table that holds a user's data must be deleted with the account: add it to the batch in
  `deleteAccount` (`src/lib/account-functions.ts`), children first.
- Routes are file-based under `src/routes/`. `src/routeTree.gen.ts` is generated by TanStack Router
  and committed — never edit it by hand; a new route needs one `pnpm build` before it typechecks.
- Styling is Tailwind CSS v4. There is no `tailwind.config.js`; theme customization goes in
  `src/styles.css`.
- Server-side logic belongs in `createServerFn` handlers or route loaders, so it runs in the Worker.
- Authentication is Better Auth with the `emailOTP` plugin (6-digit code on every sign-in). The
  instance is built per request in `src/lib/auth.ts`; read the session from the router context
  (`context.session`) rather than calling Better Auth from components.
- The database is Cloudflare D1 via Drizzle ORM. Edit `src/db/schema.ts`, then
  `pnpm db:generate --name <change>` and `pnpm db:migrate:local`; never edit `drizzle/` by hand.
- Push notifications: send with `notifyUser` (`src/lib/push.ts`); the Web Push protocol itself is
  `src/lib/web-push.ts` (WebCrypto only — never import Node's `crypto` or the `web-push` package
  into the Worker). `public/sw.js` shows them; bump its `VERSION` after changing caching rules.
- Worker configuration (bindings, compatibility flags) lives in @wrangler.jsonc . Run
  `pnpm cf-typegen` after changing bindings to refresh `worker-configuration.d.ts`. Secrets are
  declared in `src/env.d.ts`.
- `pnpm dev` starts the dev server; `pnpm dev:cf` serves the built Worker in the emulator (the only
  local run with the service worker); `pnpm e2e` runs the browser tests there; `pnpm run deploy`
  builds and ships to Cloudflare Workers.
- Manage runtimes and package managers with @mise.toml .
- AI tool configurations (`AGENTS.md`, `CLAUDE.md`, `.claude/`, `.github/instructions/`, …) are
  generated by [rulesync](https://github.com/dyoshikawa/rulesync) from `.rulesync/`. Never edit the
  generated files directly — edit `.rulesync/**` and run `pnpm generate`.
- When you want to check the entire codebase:
  - `pnpm cicheck:code` checks code style, type safety, and tests.
  - `pnpm cicheck:content` checks spelling and secrets.
  - `pnpm cicheck` checks both. Prefer this for daily checks.
- When doing `git commit`:
  - You must run `pnpm cicheck` before committing to verify quality.
  - You must not use here documents because it causes a sandbox error.
  - You must not use the `--no-verify` option because it skips pre-commit checks and causes serious
    security issues.
  - When creating a PR, you should include a link in the PR description that associates the PR with
    its issue.
- GitHub Actions must always be pinned to full-length commit SHAs. Run `mise run pinact` to pin them
  and `mise run pinact:check` to verify.
